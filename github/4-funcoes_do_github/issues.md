# Utilizando as Issues no GitHub

Quando você está utilizando o projeto de outra pessoa ou trabalhando em equipe, é comum encontrar bugs (erros no código), ter dúvidas ou pensar em melhorias para o software. No GitHub, a ferramenta oficial para organizar e discutir esses assuntos é chamada de **Issues** (que significa "problemas" ou "questões" em inglês).

Pense nas Issues como um **fórum de discussão e lista de tarefas** integrado diretamente ao repositório do projeto.


## Para que servem as Issues?

As Issues são públicas e servem principalmente para:

1. **Relatar Bugs:** Avisar o dono do repositório que algo não está funcionando como deveria (e mostrar como reproduzir o erro).
2. **Sugerir Melhorias:** Propor novas funcionalidades, mudanças no design ou ideias que possam deixar o projeto melhor.
3. **Fazer Perguntas:** Tirar dúvidas sobre o funcionamento do código ou pedir ajuda para instalar o projeto.
4. **Organizar Tarefas (To-Do List):** Se o repositório for seu, você pode criar Issues para si mesmo como lembretes das próximas tarefas que precisa programar.


## Como abrir uma nova Issue?

Qualquer pessoa que tenha uma conta no GitHub pode abrir uma Issue em um repositório público. Para fazer isso, siga estes passos:

1. Acesse a página do repositório no GitHub.
2. No menu superior (abaixo do nome do projeto), clique na aba **"Issues"** (ao lado de *Code*).
3. Clique no botão verde **"New issue"** (Nova issue) no canto direito.
4. Escreva um título claro e objetivo (ex: *"Erro na tela de login ao usar o navegador Safari"*).
5. No campo de texto, descreva o problema detalhadamente. Se for um bug, explique o passo a passo para que o dono do projeto consiga ver o erro acontecer.
6. Clique em **"Submit new issue"** para publicar.
