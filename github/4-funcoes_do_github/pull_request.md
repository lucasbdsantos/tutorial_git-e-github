# Entendendo o Pull Request no GitHub

O **Pull Request** (frequentemente chamado de **PR**) é uma das ferramentas mais importantes do GitHub. Ele é o coração do trabalho colaborativo. 

Quando você cria um Pull Request, você está dizendo ao dono de um projeto: *"Olá! Eu fiz algumas melhorias no seu código. Você poderia **puxar** essas alterações para o seu repositório original?"*.


## Como funciona o fluxo de um Pull Request?

O caminho que uma alteração faz desde a sua máquina até o projeto original geralmente segue este fluxo:

1. **O Fork:** Você faz uma cópia do projeto de outra pessoa para a sua conta do GitHub.
2. **A Alteração:** Você faz as melhorias ou corrige os erros no código dentro da sua cópia.
3. **O Envio (Push):** Você envia essas alterações para o seu GitHub.
4. **O Pull Request:** Você clica em "New Pull Request" para enviar suas alterações para análise do dono do projeto original.


## O papel do Autor do Repositório (Aceitando melhorias)

Se **você** for o dono do projeto e alguém enviar um Pull Request com uma sugestão de melhoria, o processo é extremamente simples e seguro:

1. **Análise:** O GitHub mostrará exatamente quais linhas de código a outra pessoa alterou, adicionou ou removeu.
2. **Discussão:** Você e a pessoa podem conversar, tirar dúvidas e sugerir ajustes no próprio painel do Pull Request.
3. **Aprovação (Merge):** Se você gostar das alterações e decidir aceitá-las, basta clicar no botão verde **"Merge pull request"** (Mesclar pull request). 

> ⚡ **Mágica Automática:** Assim que você clica em aprovar, o próprio GitHub junta o código da outra pessoa ao seu projeto original de forma automática. Você não precisa copiar e colar nada manualmente!
